Architecture & V2 Runtime Deep Dive

Understanding JSONPath destination filtering, atomic execution via single instructions, and the V1 vs V2 architectural shift.

The Execution Pipeline

When runOptions({ base, options, optionDefs, showLog }) is called, it processes the base AST through three distinct conditional phases in a deterministic sequence:

1
Search Bar Pipeline

Triggered when options.showSearch is truthy and optionDefs.search is defined. Filters instructions with valid JSONPath destinations and invokes json-instruction-single.

runOptions:search
2
Serial Number Column Pipeline

Triggered by options.showSerial or options.serial. Injects serial column headers into the <thead> row and counter cells into each <tr> within <tbody>.

runOptions:serial
3
Row Actions / Options Pipeline

Triggered by options.showOptions or options.options. Injects action column headers and button controls into row definitions.

runOptions:options

Inside src/v2/index.js

The V2 runner is ultra-lean, containing zero defensive bloat and zero recursive DOM parsing: 

import runSingleInstructions from "json-instruction-single";
import instructionsWithTargets from "./instructionsWithTargets/index.js";

export const runOptions = ({ base, options = {}, optionDefs = {}, showLog = false } = {}) => {
    if (!base) return base;
    const context = { base };

    // 1. Search Bar Option
    if (options.showSearch && optionDefs.search) {
        const targets = instructionsWithTargets(optionDefs.search, base);
        if (showLog) console.log("[runOptions:search]", targets);
        runSingleInstructions(targets, context, showLog);
    }

    // 2. Serial Column Option
    if ((options.showSerial || options.serial) && optionDefs.serial) {
        const targets = instructionsWithTargets(optionDefs.serial, base);
        if (showLog) console.log("[runOptions:serial]", targets);
        runSingleInstructions(targets, context, showLog);
    }

    // 3. Action Buttons Column Option
    if ((options.showOptions || options.options) && optionDefs.options) {
        const targets = instructionsWithTargets(optionDefs.options, base);
        if (showLog) console.log("[runOptions:options]", targets);
        runSingleInstructions(targets, context, showLog);
    }

    return base;
};

export default runOptions;

Safe Targeting: V2 instructionsWithTargets

The breakthrough in V2 is the use of jsonpathly to dynamically query the base AST before executing an instruction: 

import { query } from "jsonpathly";

const instructionsWithTargets = (instructions = [], base) => {
    return instructions.filter(({ destinationPath }) => {
        const jsonPath = destinationPath?.jsonPath;
        if (typeof jsonPath !== "string" || !jsonPath.trim()) return false;
        return query(base, jsonPath, { returnArray: true }).length > 0;
    });
};

export default instructionsWithTargets;
Why JSONPath Querying is Superior:
Criteria V1 (Legacy dataRole) V2 (JSONPath via jsonpathly)
Target Pattern destinationPath.dataRole = "tableRoot" destinationPath.jsonPath = "$..*[?(@.tag == 'thead')]"
AST Traversal Manual recursive tree walk Optimized JSONPath evaluator engine
Selector Range Only elements tagged with data-role Any attribute, tag name, index, or hierarchy
Crash Safety Can fail on non-standard tree nodes Pure filter: non-matching instructions safely dropped
